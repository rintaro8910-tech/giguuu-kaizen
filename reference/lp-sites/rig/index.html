Introducing Rig

Automated Security
Inside the Loop

Rig checks the application when the coding agent finishes its work. Findings go straight back to the agent, while the code and context are still fresh.

THE LOOP / 01

The agent finishes a change. Rig starts a check.

Rig connects to the agent’s completion hook. The check starts automatically, without a developer remembering to run a scan.

THE LOOP / 02

Rig tests the running application.

Rig runs the application locally and tracks how input moves through its code. It confirms a vulnerable execution path before reporting a finding.

THE LOOP / 03

The agent gets evidence and fix instructions.

Each finding identifies the code location, explains the vulnerability, and gives the agent guidance for fixing it. The same agent working on the feature can act on that feedback.

THE LOOP / 04

Rig checks the updated code.

After the agent makes a fix, Rig retests the reported vulnerability. The result shows whether the check passed, the issue remains, or testing could not complete.

The Difference

Static analysis reads the code.
Rig tests what it does.

Static analysis finds potential vulnerabilities in source code. Rig adds evidence from the running application, separating what could happen from what happened during a test.

01

Reachability, confirmed.

Static analysis can identify a potentially vulnerable path. Rig confirms that the path actually executes in the running application before reporting a finding.

02

Runtime context, included.

Static analysis models how code may behave. Rig observes how it behaves with the inputs, configuration, and dependencies present during the test.

03

Evidence, ready to act on.

A static finding can leave developers checking whether an issue is reachable. Rig includes execution evidence and the code location, giving developers and agents concrete fix instructions.

FAQ

Frequently asked questions.

01Does Rig work with my existing coding agents?

Rig connects to a supported coding agent through its completion hook. During the demo, we’ll review the team’s agent and application to confirm fit.

02Who makes the code changes / fixes to reported vulnerabilities?

Your existing coding agent makes the fix. Rig supplies the finding, code location, and fix guidance, then checks the updated code.

03Is Rig checking every keystroke?

No. The automatic check starts when the agent signals that it has finished its work. Developers can also run a check manually through the CL

04What happens if a fix does not work?

Rig reports that the vulnerability remains. If testing cannot complete, that is reported separately from a passed check.

05Does a clean scan mean the entire application is secure?

No. It means Rig completed the checks within that scan’s scope without confirming a vulnerability. Untested paths are not proven safe, and incomplete checks are reported separately.

06Will Rig Collect my Data?

No, Rig is committed to being the most secure and private security testing tool available.. Our telemetry is limited. Tests run on device and code and conversations never leave the machine.
